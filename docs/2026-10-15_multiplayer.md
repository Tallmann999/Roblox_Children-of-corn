## Правила первой версии

- Локальный Studio DEV-тест на ПК, 1–4 игрока. Внешние режимы/non-Studio
  не запускают этот coordinator. Четыре существующих угловых старта
  распределяются без повторов. Ни лобби-карта, ни matchmaking не добавляются.
- Один раунд, одна карта630, один переносимый ключ, одни ворота и один общий
  финальный таймер120 секунд. Hard/ночь и существующая охота сохраняются:
  обнаружение48studs до ворот,96у всех3NPC после открытия.
- Каждый подключённый участник подтверждает готовность существующей кнопкой
  начала/повтора. Все готовы — сервер начинает раунд. Позднее подключение
  ждёт следующего раунда. Игрок сверх лимита также видит ожидание.
- У каждого личные выносливость, пять слотов, две поимки, мини-карта посещений,
  сцена захвата и результат. На карте общие2энергетика/2капкана; один предмет
  нельзя подобрать дважды. Это сохраняет текущий баланс для первой проверки.
- Ключ занимает слот только у носителя. Остальные видят имя носителя, без
  координат. При любой поимке, смерти, отказе или отключении носителя ключ
  падает в доступной точке; резерв — исходный безопасный слот. Ключ не теряется
  вместе с последним слотом/персонажем. Открытие ворот потребляет его один раз.
- Любой живой участник пересекает открытый выход и получает20 сессионных
  алмазов ровно один раз. Побег/поражение/выход одного не останавливает других.
  Следующий раунд доступен, когда все участники завершили текущий или ушли.
- Первая поимка: личная сцена1сек и выбор возрождения у своего старта с прежней
  защитой5сек. Остальные продолжают. Таймер команды не замораживается.
  Вторая поимка завершает только личную попытку. Reset также завершает её.
- Каждый NPC выбирает серверную цель среди активных игроков и двигается один
  раз за тик. Погоня сохраняет выбранную цель до потери/недоступности.
  Захват на1сек останавливает только захватившего NPC; чужое возрождение не
  снимает капкан и не возвращает остальных NPC домой.
- Непрерывный шелест сохраняет независимые Pause/Resume курсоры. Один общий
  серверный аудиопланировщик учитывает только активных участников; личная Hunt
  звучит только у серверной цели. Ожидающие/выбывшие не создают движение кукурузы.
  При личной поимке планировщик продолжает общий active раунд; фон, чужой
  шелест и остальные NPC не ставятся на общую паузу. Пойманный игрок исключён
  из movement eligibility до личного revive.
- Сохранённые крики появления остаются отдельными Root-bound Sound:
  Monster2 — COC_Monster_01/100872584572146, Monster3 — COC_Monster_02/92691373477671,
  Effects/Volume0.95/Linear20..1400/Loopedfalse. TeamRound уведомляет
  `RoundAudio:ReinforcementsSpawned` один раз после успешного создания обеих
  сущностей и commit120-секундного deadline. Частичный/неудачный spawn не
  вызывает крик; ошибка аудио не отменяет успешные ворота. Повторный prompt,
  sync/lead/root handoff, revive и освобождение капкана не переигрывают arrival.
  SoundId и курсоры rustle не меняются, новых preload ID или remotes нет.

Автор подтвердил лимит4 с возможностью solo, общий ключ, личные две поимки
и20алмазов за побег, следующий раунд после результата всех и ожидание поздних
подключений. Готовность всех перед стартом оформляет этот общий цикл.

## Сетевой контракт и владение

Существующие четыре gameplay RemoteEvent сохраняются. Клиент передаёт только
прежние действия, номер слота и sprint intent. Состав команды, цель NPC, ключ,
предметы, выход, награда, время и переходы раунда принадлежат серверу. Входящий
Player берётся из OnServerEvent/Triggered, не из клиентского payload.

`round_snapshot` остаётся личным и расширяется полем `team`:

| Поле | Значение |
|---|---|
| round_id | целое >=0, меняется при старте нового раунда |
| state | waiting / preparing / active / finished |
| capacity / count | 4 / число допущенных подключённых игроков0..4 |
| ready_count / ready | сколько готовы / готов ли получатель |
| remaining | незавершившие участники текущего раунда0..count |
| can_start | сервер разрешает получателю подтвердить следующий старт |
| key_state | hidden / carried / opened |
| carrier_name | имя носителя, строка до50символов; без координат |

`has_key`, inventory, catches, capture, stamina, minimap, reward и
`monster_state` относятся к получателю. `gate_open`/evacuation общие, но
таймер показывается только продолжающим участникам. Поимка/выход одного
не отключает чужие prompts. Лимиты запросов и транзакции личные; pickup,
открытие ворот и выдача награды выполняются без yield между проверкой и commit.

Один TeamRound владеет runtime миром/предметами/ключом/NPC/Lighting/audio.
RoundParticipant хранит личное состояние и повторно использует проверенные
личные movement/interaction helpers SoloRound. Старый SoloRound не запускается
параллельно и остаётся для исторических fixtures. Новых постоянных world tags
или геометрии нет. Допустимы только2новых ModuleScript в GameServer/Game и
объявленные изменения существующих Sources. Поле, Lighting вне runtime,
импортированный арт и raw Terrain сохраняются точно.
Текущие Balance/SoloRound из принятого entity-arrival baseline не заменяются
старыми файлами архива. Радиусы48/96 и arrival API сохраняются; общий
RoundAudio добавляет server eligibility для действующих участников/целей.

## Приёмка

1. Локальные проверки гонок pickup/gate, выпадения ключа, независимых попыток,
   наград, revive, reset, disconnect, позднего подключения и готовности.
2. NPC выбирает/теряет цели, не ускоряется от числа игроков; капкан переживает
   чужое возрождение. Аудио исключает ожидающих и остановленных участников,
   продолжает shared active при личном caught и сохраняет однократные крики
   обеих сущностей/48→96 detection. Частичный spawn и throwing audio проверяются
   отдельно от успешной транзакции открытия ворот.
3. `check.ps1`, актуальные audio/corn/inventory regressions и новые fixtures.
4. Настоящий Studio server с минимум2клиентами: личные snapshots/HUD,
   один ключ/ворота/таймер, побег одного при продолжающем другом, повтор,
   late join и disconnect. Adapter/fake Player не заменяет эту приёмку.
5. Code-only guarded installer в проверенном stopped Children_of_corn;
   отказ при неизвестных Sources/топологии/open tabs, rollback и repeat0.
6. Точный engine save проверяется новым multiplayer verifier против immutable
   before-multiplayer-resume997184/b5ef0471…; источники и мир должны соответствовать
   актуальным build-multiplayer-installer.py/verify-multiplayer-copy.py. Никакой
   сериализации сцены через Lune; promotion только
   для отдельного проверенного кандидата с обоими защищёнными хэшами.

Persistence/покупки/публикация не входят. Реальные результаты и ограничения
записываются после тестов; этот документ сам по себе не доказывает готовность.
