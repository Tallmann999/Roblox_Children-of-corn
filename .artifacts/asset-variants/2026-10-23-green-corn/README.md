# Зелёная кукуруза: три формы — 23 октября 2026

Создано в отдельном Blender 5.2.2 LTS процессе из точного исходного
`SM_Prop_Plant_Corn_01_L.fbx` (SHA256 `259fbe167d4c0a24e6813282a5f3026d582b67d7af1f701bad39bed706a193df`).
Исходный FBX и зелёный PNG сохранены байт в байт.

В корне проекта находятся три FBX:

- `SM_Prop_Plant_Corn_01_L_Var_01.fbx`: изогнутый стебель и смещённая верхняя крона.
- `SM_Prop_Plant_Corn_01_L_Var_02.fbx`: более широкие листья с мягким опусканием наружной части.
- `SM_Prop_Plant_Corn_01_L_Var_03.fbx`: поворот формы по высоте и другое положение листьев.

Это деформация геометрии, а не три поворота одного объекта.
Каждая модель содержит 377 вершин, 510 треугольников, один материал,
один исходный UV-канал и исходный `colorSet1`.
Нет арматуры, анимаций или дополнительных текстур.
`Green_Corn_Variants.blend` хранит исходную нормализованную форму и три варианта.

## Проверки

`manifest.json` содержит точные пути, размеры, хэши FBX/JSON/ModuleScripts,
bounds, root offsets и радиусы растений. `build-report.json` содержит
полные результаты Blender, QA, статистики и повторного импорта.

Геометрическая QA прошла для всех четырёх форм: нет новых инверсий,
вырожденных граней, плавающих элементов или coplanar z-fighting.
Сырой QA отдельно отмечает 510 треугольников с нулевой UV-площадью:
это сохранённая палитровая разметка исходных 302 полигонов, а не ошибка
unwrap. Отдельно приняты 218 исходных открытых рёбер тонкой листвы.
Runtime использует DoubleSided и не использует меш как физический коллайдер.
Зелёный атлас 1254×1254 сохранён; он превышает рекомендацию 1024 из skill,
но находится ниже предела 4096 и является одной общей текстурой.

FBX повторно импортированы независимо. Все 510 треугольников сопоставлены;
максимальная ошибка позиции — 0.000000358 м, UV — 0,
нормали — 0.000336 по длине разности единичных векторов.
Небольшое отклонение нормалей связано с кодированием custom normals при
повторном FBX-импорте и укладывается в заявленный допуск 0.0005.
Исходный colorSet1 сохранился: все 1530 значений углов каждого варианта
совпали после округления до пяти знаков.

Восемь обязательных material/wire contact sheets и дополнительный настоящий
EEVEE textured comparison просмотрены. `green-variants-textured-comparison.png`
показывает все четыре формы на одной шкале. Палитровый PNG напрямую подключён
к BaseColor; colorSet1 не умножается на цвет — это исходный non-albedo
канал с нулевым зелёным компонентом.

## Runtime contract

`Original-runtime.json`, `Var01-runtime.json`, `Var02-runtime.json`,
`Var03-runtime.json` содержат позиции, треугольники, точные corner UV,
нормали и сохранённый corner color-канал. Runtime ModuleScripts Var01/02/03
созданы отдельно под `variants/B/shared/Game/CornGreenGeometryData`.
Они не подключают или изменяют Studio.

Blender: метры, +Z вверх, actual stem base в (0,0,0).
Runtime: [x,z,-y], номинальная высота 8 studs, позиции центрированы
относительно bounding box.
`root_offset_studs` — реальный корень минус центр bounds;
`bbox_center_from_root_studs` — противоположный вектор.
При вертикальной variation корректная позиция центра MeshPart:

```luau
rootFrame * yawFrame * CFrame.new(center.X, center.Y * actualHeight / 8, center.Z)
```

Ширина и глубина не зависят от height variation. Нельзя предполагать, что
корень наклонённых моделей находится прямо под центром bounding box.
Максимальные горизонтальные радиусы от реального корня:
Original 1.589463, Var01 2.265399, Var02 2.006129, Var03 2.398614 studs.

`source_sha256` и `original_source_sha256` относятся к исходному авторскому
FBX. `exported_fbx_sha256` отдельно связывает данные с конкретным новым FBX.
Runtime должен использовать зелёный атлас и белый tint без применения
non-albedo colorSet1 к BaseColor.

## Воспроизведение

1. Запустить Blender headless с `build-variants.py` — он создаёт собственные
   артефакты и три FBX, не меняя исходные файлы.
2. Запустить `freeze-data.py`, затем StyLua для трёх новых ModuleScripts.
3. Запустить Blender с `verify-color-roundtrip.py`.
4. Для общего textured preview открыть сохранённый blend headless и
   выполнить `render-comparison.py`; этот скрипт не сохраняет blend.

Повторная FBX-выгрузка может менять FBX metadata и SHA256. Не перегенерировать
эти замороженные файлы поверх будущих runtime/save manifests автоматически.
Нет Studio-изменений, публикации ассетов или приёмки игрового FPS.
